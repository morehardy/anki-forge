1: # Build and output guarantees
2:
3: `Project::build` returns `BuildOutput` only after a successful operation, with a
4: guaranteed APKG artifact. A failed operation returns `BuildError` with structured
5: kind/code, observations, underlying causes and actual publication facts.
6:
7: ## Temporary and persistent artifacts
8:
9: Choose the ownership model explicitly:
10:
11: | Request | Ownership |
12: | --- | --- |
13: | `BuildOptions::to(path)` | Persistent destination; survives handle cleanup |
14: | `BuildOptions::temporary()` | Temporary file; deleted with its last artifact owner |
15: | `artifact.persist_to(path)` | New persistent owner; original owner remains usable |
16:
17: Keep the `BuildOutput` or a cloned artifact alive while reading a temporary
18: path. A report or JSON snapshot does not extend file lifetime. Rust drops owners
19: normally; Node exposes `artifact.close()` for deterministic release. Copying the
20: path into application state does not create an owner.
21:
22: Rust artifact handles retain absolute paths, including when the build or
23: `persist_to` uses a relative destination. Later changes to the process working
24: directory do not redirect reads or copies from an existing handle. Each new
25: `persist_to` destination is resolved against the directory at that call.
26:
27: `BuildReport::snapshot()` contains only observations. `BuildOutput::snapshot()`
28: and `BuildError::snapshot()` additionally state the real outcome. A warning can
29: appear in a successful snapshot. Do not infer outcome from diagnostic severity,
30: a path's existence, or whether a report has comparison findings.
31:
32: ## Baselines and publication
33:
34: For updates, retain the previous original distribution APKG as an immutable
35: baseline and choose a separate output destination. Baseline evidence and
36: candidate content are checked before publication. Policy rejection does not
37: replace the output. Missing or corrupt evidence and exhausted inspection budgets
38: are hard failures.
39:
40: Publication uses atomic replacement of the APKG. This is a per-file guarantee;
41: writing an application's separate JSON report is a separate operation. The
42: ordinary build does not write an additional identity file: complete versioned
43: evidence is embedded in the distribution package.
44:
45: A late error can occur after publication, for example while confirming
46: persistence. Error snapshots therefore record `PublicationSnapshot` facts:
47: `path`, `stage` (`not_published` or `published`), `temporary`, and durability
48: (`confirmed` or `unconfirmed`). Check these facts before retrying or announcing
49: that no file was written. `PersistError` also preserves its publication fact and
50: actual I/O source. Atomic replacement alone does not establish durability after
51: a crash.
52:
53: Snapshot serialization preserves native paths without accessing the filesystem.
54: Unicode paths remain JSON strings. Non-UTF-8 Unix paths use
55: `{"encoding":"unix_bytes","bytes":[...]}`; Windows paths with unpaired UTF-16
56: surrogates use `{"encoding":"windows_wide","units":[...]}`. The arrays contain
57: the exact native bytes or code units. Success artifact paths, failure publication
58: paths, and binding error-path details all use this representation. These values
59: describe paths and do not retain artifact ownership. A filesystem may reject a
60: particular native path, but its publication failure facts remain serializable.
61:
62: ## Inspection limits
63:
64: Finite archive, entry-count, expansion, decoded collection/media and zstd-window
65: budgets apply independently to baseline and candidate. Start with
66: `InspectLimits::default()` and deliberately raise a relevant limit when needed.
67: A limit of zero is not unlimited. These counters are not a process-wide memory
68: or CPU sandbox; media imports have a separate earlier per-asset budget.
69:
70: ## Concurrent work
71:
72: Rust builds borrow immutable project state. Owned models and media can be shared
73: across projects. The Node binding captures a project snapshot when build or
74: compare is invoked, so later additions do not change that request. Retain the
75: artifact owner until all readers have finished; closing the last temporary owner
76: while a separate consumer still needs its path is an application lifetime error.
77:
78: Package inspection cannot establish every client-side behavior. Test rendering,
79: playback and update imports with the intended Anki versions and settings. See
80: [updates](updates.md) for scheduling and schema-change limits.
81:
82: <!-- section: prepared-publication-from-source -->
83: ## Prepare, review and publish
84:
85: Prepared publication is included in the public `0.3.1` packages.
86:
87: `prepare_publication` builds, inspects and compares one private candidate;
88: `publish` uses that same file. Options and relative destinations bind at
89: preparation. Project edits cannot alter the candidate. Preparation alone does
90: not replace the destination; dropping or closing an unpublished owner removes it.
91:
92: Every publish attempt consumes the owner, including policy or I/O failure.
93: Reprepare to retry or change the policy/destination. Reports remain readable and
94: own no files. Node/Python expose idempotent `close()` and an unavailable error
95: with `closed` or `consumed` reason; closing after publication starts does not
96: cancel it. Duration excludes review waiting. A late durability failure can
97: follow successful replacement, so inspect the actual publication facts.
98:
99: Follow the [complete example](updates.md#build-once-review-then-publish-from-source)
100: and the language API references for typed errors and worker behavior.

FILE docs/python/api.md
1: # Python API
2:
3: The SDK calls the default Rust public API through a native extension. It includes `py.typed` and checked public signatures. Start with the [quickstart](quick-start.md).
4:
5: ## Project and note values
6:
7: | Entry | Behavior |
8: | --- | --- |
9: | `Project(namespace, *, default_deck=None)` | Validates the explicit stable namespace and configures the default deck |
10: | `project.add(key, note)` | Atomically collects the note, model and owned media; duplicate note keys fail |
11: | `project.add_asset(media)` | Includes an explicit raw HTML/CSS/script dependency |
12: | `len(project)` | Number of successfully added notes |
13: | `Note.basic(front, back)` | Built-in Basic model; strings mean Text |
14: | `Note.cloze(text)` | Built-in Cloze model; strings mean Text and retain cloze syntax |
15: | `note.field(key, content)` | Returns a new note with the field assignment; key validation occurs on add |
16: | `note.deck(name)` / `.tag(tag)` / `.tags(tags)` | Returns a configured note |
17: | `note.note_type` | The immutable owned model |
18:
19: Ordinary strings become Text. `Content.text(value)` and `Content.html(value)` are explicit constructors; `Content.sequence(iterable)` composes strings and content without rendering or losing media dependencies. A field does not accept a raw filename as a media reference.
20:
21: ## Models and templates
22:
23: `NoteType.builder(key)` returns an immutable builder. Its `.name`, `.field`, `.template`, `.css`, `.cloze_field` and `.asset` methods return updated builders. `.build()` validates the complete definition and returns an immutable NoteType. `model.note()` creates a note owning that model. `NoteType.from_bundle(path, limits=MediaLimits())` loads the same model and its assets from the current bundle format; the optional budget applies separately to each asset before reading.
24:
25: `Field(key, name=None, required=False, sort=False)` separates the stable key from the display name. `Template(key, front, back, name=None, browser_front=None, browser_back=None, target_deck=None, generation=GenerationRule())` uses field keys in every source string. `GenerationRule.all(keys)` and `.any(keys)` configure card generation. The default infers Anki's field-presence condition. A builder's `.cloze_field(key)` declares custom cloze generation.
26:
27: ## Media and occlusion
28:
29: | Entry | Behavior |
30: | --- | --- |
31: | `Media.file(path, *, limits=MediaLimits())` | Reads an owned snapshot immediately |
32: | `Media.bytes(data, media_type, *, limits=MediaLimits())` | Owns bytes with an explicit MIME type |
33: | `media.with_export_name(name)` | Returns a new filename value sharing the snapshot; previous references retain their names |
34: | `media.filename`, `media.media_type`, `len(media)` | Read-only snapshot metadata |
35: | `media.image()` / `.sound()` | Typed content that retains the snapshot |
36:
37: `MediaLimits(max_bytes=256 << 20)` controls each import before snapshot creation. Large media can spill to owned temporary storage. Naming conflicts are validated across all explicit and automatically collected assets.
38:
39: `Note.image_occlusion(media)` returns an ImageOcclusionBuilder. Chain `.mask(Mask.rect(key, x, y, width, height))`, optionally `.mode(OcclusionMode.HIDE_ONE_GUESS_ONE)`, then `.build()`. The default mode is `HIDE_ALL_GUESS_ONE`. Completion decodes the image and validates stable mask keys and finite in-bounds pixel coordinates. On the returned Note, set `header`, `back_extra` or `comments` normally. The generated `image` and `occlusion` fields cannot be assigned manually.
40:
41: ## Operations and results
42:
43: | Entry | Result |
44: | --- | --- |
45: | `project.build(BuildOptions.to(path))` | BuildOutput with a guaranteed persistent artifact |
46: | `project.build(BuildOptions.temporary())` | BuildOutput with an owned temporary artifact |
47: | `options.update_from(path)` | Returns options for updating from complete baseline evidence |
48: | `project.compare(CompareOptions.against(path))` | Completed ComparisonReport, including a separate publication policy decision |
49: | `options.update_policy(policy)` | Applies explicit risk policy to Update/Compare; invalid for Create |
50: | `options.inspect_limits(limits)` | Applies finite limits independently to baseline and candidate |
51:
52: BuildOutput has `.artifact`, `.report` and `.snapshot()`. BuildReport exposes `.counts` (BuildCounts with notes/cards/media), `.diagnostics`, `.comparison` and `.snapshot()`. A report has no outcome or file owner. ComparisonReport exposes `.findings`, `.policy`, `.allows_publication` and `.snapshot()`. Snapshots are ordinary JSON-serializable dictionaries and contain no artifact ownership.
53:
54: ApkgArtifact exposes `.path`, `.persist_to(path)` and `.close()`. Copying it with `copy.copy` retains another owner; a context manager releases that owner on exit. Temporary output disappears when its last owner is released. Persistent paths survive handle cleanup. A failed persist keeps the source handle usable.
55:
56: `UpdatePolicy()` blocks High and Critical findings. `.fail_on(RiskLevel.MEDIUM)` changes the threshold. `.allow('RISK.NOTE_REMOVED')` explicitly accepts the whole registered category, preserving evidence. Unknown codes fail immediately. `InspectLimits` exposes all finite byte/count budgets, including `max_identity_bytes`; it cannot disable required inspections.
57:
58: ## Errors and concurrency
59:
60: Failures raise SchemaError, AddError, MediaError, ImageOcclusionError, TemplateBundleError, CompareError, PolicyError, BuildError or PersistError. Each exposes `kind`, `code`, `details`, structured observations in `source_details`, and source-chain text in `causes`, and retains the native exception as `__cause__`. I/O causes retain a chained OSError where available. BuildError provides `.report` and `.snapshot()`; CompareError provides partial `.report`; PersistError details include actual publication facts.
61:
62: Native Project operations release the GIL and reject simultaneous use of the same object with `BINDING.PROJECT_BUSY`; independent projects can run concurrently. After a process fork, recreate all native values and handles. Inherited handles reject operations with `BINDING.FORKED_OBJECT`, and their cleanup cannot remove parent-owned files. Child-created values operate and clean up normally. See [diagnostics](diagnostics.md).
63:
64: ## Addition context
65:
66: Failed additions leave the project unchanged. Structured context records the
67: original note/model keys and the target, with optional conflict or media usage
68: details. Rust exposes `note::{AddContext, AddTarget, AddDetail}` through
69: `AddError::context()` / `detail()`; SDKs expose `AddError.details` with typed
70: context/detail. Node fields use camelCase and are deeply frozen; Python uses
71: snake_case TypedDicts. Tags retain their insertion index; field locations retain
72: original sequence indices (null/None for the field, [] for its root) and optional
73: UTF-8 byte ranges. Default-deck errors from build have no note/model keys and
74: remain available in the source chain.
75:
76: Typed images require image/* MIME at addition; sound references accept audio/*
77: or video/*. Other categories raise `NOTE.MEDIA_USAGE_INVALID`. Constructors stay
78: infallible; explicit assets and raw HTML are unaffected. The check uses retained
79: import MIME, and does not certify playback. Build's independent MIME/extension
80: validation still applies. See [the design](../plans/2026-09-28-rust-api-validation-and-errors-design.md) for the complete target/detail table.
81:
82: <!-- section: source-api-details -->
83: ## Batch media and prepared publication
84:
85: Batch media and prepared publication are included in the public `0.3.1` package.
86:
87: ### Prepare, review and publish
88:
108:
109: One publish attempt consumes the owner, including policy or I/O failure. Later
110: calls raise `PreparedPublicationStateError` with code `BUILD.PREPARED_UNAVAILABLE`
111: and reason `closed` or `consumed`; close does not cancel an already running
112: publication. Relative paths bind at preparation invocation, and Project changes
113: cannot modify the reviewed APKG. Reports survive close without retaining files.
114: Change options or retry by preparing again. Duration excludes review waiting.
115: Late errors can mean replacement succeeded with unconfirmed durability; inspect
116: publication facts before deciding what to do. Native binding protocol 1 and
117: contract bundle 2.1.0 are required; older same-version binaries are rejected.

2:

49: ## Policy and inspection limits
50:
51: This full program selects a stricter threshold and uses the same configuration
52: for comparison and update:
53:
76:
77: The default policy blocks High and Critical findings. After reviewing a specific
78: category, a caller can deliberately choose
79: `UpdatePolicy::default().allow(RiskCode::NoteRemoved)`. It accepts **all findings
80: in that category**, retaining their original level and evidence. It does not
81: claim to approve selected notes individually. An allowance with no matching
82: finding produces a warning; unknown risk codes are rejected. Do not automatically
83: allow every code returned by a comparison.
84:
85: Missing or corrupt evidence, namespace mismatch, invalid candidate data and
86: inspection limits are hard errors, not allowable risk categories. Comparison
87: returns an error with completed observations when analysis cannot finish.
88: Explicit policy on a create request without `update_from` is a configuration
89: error regardless of setter order.
90:
91: ## Evidence and identity
92:
93: The package includes `ankiforge-identity.json` with the
94: `ankiforge-identity-v1` format. It binds model/config IDs, note GUIDs, historical
95: field/template slots, card/mask ordinals, revisions and media to the actual
96: collection and payloads. Anki re-export does not preserve this evidence and is
97: not a usable update baseline. Missing evidence is never silently reconstructed.
98:
99: Display-name and content edits preserve identity keys. Unchanged content keeps
100: its baseline revision; changed content advances it. Reordering fields/templates
101: preserves historical mappings. Retired identities remain reserved so that
102: restoring the same key can reuse them. A note key cannot move to another model,
103: and a model key cannot change between normal and Cloze kinds.
104:
105: ## Client import behavior and release review
106:
107: An APKG is a distribution package, not deletion synchronization. Omitting notes,
108: fields, templates or masks does not delete existing learner data. Field/template
109: schema changes and sort-field changes are high-risk because Anki merge and import
110: settings affect their behavior. Schema changes can copy models or update target
111: note timestamps before note-content comparison.
112:
113: Test first import and updates into an existing collection on the clients you
114: support. Check fields, GUIDs, card sets, local edits and existing scheduling with
115: the intended merge and note-update settings. Stable identity alone does not
116: promise that newer local edits are overwritten or deleted history is restored.
117:
118: Write candidates to a path separate from the archived baseline. After review,
119: distribute the accepted package and retain it as the next release's evidence.
120: See [build guarantees](build-guarantees.md) for ownership and publication facts.
