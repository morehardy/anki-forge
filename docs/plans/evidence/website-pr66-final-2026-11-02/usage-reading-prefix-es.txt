Importar un paquete no elimina las notas que se hayan omitido en un paquete posterior. Comparar o generar correctamente un paquete no garantiza el estado de repaso de cada estudiante.

original-baseline-update http://127.0.0.1:63533/anki-forge/es/docs/updates/
Actualiza mazos de Anki con ID de nota estables

Publica correcciones o tarjetas nuevas para un mazo de Anki que ya hayas distribuido. Los ID de nota estables ayudan a Anki Forge y a Anki a reconocer las notas existentes en lugar de tratarlas como nuevas; las opciones de importación de Anki y los cambios locales más recientes también influyen en lo que se actualiza.

Mantén estables el espacio de nombres del proyecto y las claves de notas, modelos, campos y plantillas. Genera cada versión nueva a partir del APKG original de distribución anterior, que contiene pruebas completas de identidad con su versión de formato. Guarda ese paquete junto con la revisión de su código fuente.

Política y límites de inspección
Sección titulada «Política y límites de inspección»

Este programa completo elige un umbral más estricto y utiliza la misma configuración para la comparación y la actualización:

[Rendered code/command: captured and separately bound in browser-tour.json]

La política predeterminada bloquea los hallazgos High y Critical. Tras revisar una categoría concreta, puedes elegir de forma deliberada UpdatePolicy::default().allow(RiskCode::NoteRemoved). Esta opción acepta todos los hallazgos de esa categoría, conservando su nivel original y sus pruebas. No significa que se hayan aprobado notas concretas de forma individual. Una excepción sin hallazgos coincidentes produce una advertencia; se rechazan los códigos de riesgo desconocidos. No autorices automáticamente todos los códigos que devuelva una comparación.

La ausencia o corrupción de las pruebas de identidad, un espacio de nombres distinto, los datos no válidos de la versión candidata y la superación de los límites de inspección son errores, no categorías de riesgo que se puedan autorizar. Si el análisis no puede terminar, la comparación devuelve un error con las observaciones que haya completado. Establecer una política explícita en una solicitud de creación sin update_from es un error de configuración, independientemente del orden de las llamadas a los métodos de configuración.

Pruebas e identidad
Sección titulada «Pruebas e identidad»

El paquete incluye ankiforge-identity.json con el formato ankiforge-identity-v1. Vincula los ID de modelos y configuraciones, los GUID de notas, las posiciones históricas de campos y plantillas, los números ordinales de tarjetas y máscaras, las revisiones y los recursos multimedia con la colección y los datos reales. La reexportación desde Anki no conserva estas pruebas y no sirve como base de una actualización. Las pruebas ausentes nunca se reconstruyen de forma silenciosa.

Las ediciones de nombres visibles y contenido conservan las claves de identidad. El contenido que no cambia mantiene la revisión de su base; el contenido modificado avanza de revisión. Reordenar campos o plantillas conserva sus correspondencias históricas. Las identidades retiradas permanecen reservadas para poder reutilizarlas al restaurar la misma clave. Una clave de nota no se puede trasladar a otro modelo, y una clave de modelo no puede cambiar entre los tipos normal y Cloze.

Importación en el cliente y revisión de versiones
Sección titulada «Importación en el cliente y revisión de versiones»

Un APKG es un paquete de distribución; no sincroniza eliminaciones. Omitir notas, campos, plantillas o máscaras no elimina los datos existentes de quienes estudian. Los cambios de esquema de campos o plantillas y los cambios del campo de ordenación tienen riesgo alto porque su comportamiento depende de cómo Anki combine e importe los datos. Los cambios de esquema pueden copiar modelos o actualizar las marcas de tiempo de las notas de destino antes de comparar su contenido.

Prueba la primera importación y las actualizaciones de una colección existente en los clientes que admitas. Comprueba los campos, los GUID, los conjuntos de tarjetas, las ediciones locales y la programación de repaso existente con la configuración de combinación y actualización de notas prevista. La identidad estable, por sí sola, no garantiza que se sobrescriban ediciones locales más recientes ni que se restaure un historial eliminado.

Escribe las versiones candidatas en una ruta distinta de la base archivada. Tras la revisión, distribuye el paquete aceptado y consérvalo como prueba para la siguiente versión. Consulta las garantías de generación para conocer cómo se conservan los archivos y cómo se publican.

troubleshooting http://127.0.0.1:63533/anki-forge/es/docs/troubleshooting/
Soluciona errores de Anki Forge

Usa los valores estructurados kind y code de la operación fallida, junto con su cadena de causas y sus observaciones. El texto visible está pensado para las personas y puede cambiar. Una operación fallida y una comparación completada cuya política bloquea la publicación son resultados distintos.

Instalación
Sección titulada «Instalación»
Síntoma	Comprobación
Rust rechaza la versión de las herramientas	Ejecuta rustc --version; usa Rust 1.92+ y comprueba la versión instalada con cargo tree -i ankiforge
Node no puede cargar su paquete nativo	Ejecuta node -p "process.platform + '/' + process.arch" y npm ls ankiforge; reinstala con npm install --include=optional ankiforge@0.3.1
Node indica que las versiones del componente nativo y del módulo JavaScript no coinciden	Usa versiones coincidentes; reinstala ambos desde la misma versión del registro o recompílalos desde el mismo repositorio descargado
Python no puede cargar su extensión	Ejecuta python -m pip show ankiforge y python -m pip debug --verbose; comprueba el intérprete y las etiquetas de SO/CPU del wheel
Python elige una distribución de código fuente	Elige un wheel y un intérprete compatibles, o sigue la compilación desde el código fuente con un compilador

Consulta los entornos verificados, la configuración de Node y la configuración de Python.

Modelos y notas
Sección titulada «Modelos y notas»
Síntoma	Corrección
Clave no válida o vacía	Indica una clave estable explícita; los nombres visibles son independientes
NOTE.KEY_DUPLICATE	Asigna una clave única a cada registro lógico de origen
NOTE.FIELD_UNKNOWN	Usa la clave del campo, no su nombre visible
NOTE.FIELD_REQUIRED	Rellena los campos declarados con required() antes de añadir la nota
NOTE.MODEL_CONFLICT	Reutiliza el mismo modelo finalizado para una misma clave de modelo
Error de referencia de plantilla	Utiliza las claves declaradas en las plantillas; inspecciona el intervalo de bytes del origen
El HTML aparece como texto literal	Usa Content::html solo cuando quieras incluir marcado
Faltan tarjetas Cloze	Indica la sintaxis {{c1::answer}} con números admitidos del 1 al 500

El fallo de una adición es atómico. Corrige la nota o el modelo y vuelve a intentarlo; no hay que deshacer ningún registro parcial de modelos o recursos multimedia. Los constructores de modelos deben terminar con .build() antes de poder crear notas personalizadas.

Recursos multimedia y plantillas
Sección titulada «Recursos multimedia y plantillas»
Síntoma	Corrección
Falla la importación de un archivo	Comprueba el origen al llamar a Media::file; después de importarlo se puede eliminar el archivo de origen
El MIME no coincide con el contenido	Pasa el tipo MIME real al constructor de bytes
Conflicto de nombres de exportación	Elige nombres portables únicos; las variantes de mayúsculas o normalización Unicode también entran en conflicto
Falta un recurso de HTML, CSS o script sin procesar	Decláralo con asset en el modelo o con add_asset en el proyecto
La importación multimedia supera un límite	Aumenta explícitamente MediaLimits.max_bytes antes de importar
La inspección de generación supera un límite	Ajusta el contador de InspectLimits pertinente para la operación
Falla la carga de un paquete de plantillas	Usa bundle-v2, claves explícitas, plantillas que referencien claves y rutas dentro del paquete
Falla un rectángulo de oclusión de imágenes	Comprueba las dimensiones decodificadas que se muestran, las coordenadas finitas y las claves únicas de las máscaras

Los valores de texto predeterminados son uniformes en todos los tipos de nota. Los nodos multimedia incorporan sus dependencias; escribir un nombre de archivo a mano no importa sus bytes. Un paquete válido sigue necesitando pruebas de reproducción en el cliente con el códec o la fuente que quieras utilizar.

Actualizaciones y archivos de salida
Sección titulada «Actualizaciones y archivos de salida»

Usa como base un APKG original de distribución que contenga pruebas completas de identidad. Los paquetes reexportados desde Anki no conservan esas pruebas. Una política de actualización no puede aceptar un espacio de nombres distinto ni pruebas dañadas.

Una comparación completada puede tener allows_publication == false. Inspecciona los hallazgos originales y sus pruebas antes de elegir una excepción explícita para una categoría de riesgo. No autorices todos los resultados sin revisarlos. Debes pasar la misma política a la generación real de la actualización si quieres obtener la misma decisión. Establecer una política en una solicitud que solo crea un paquete es un error.

Si desaparece una ruta temporal, conserva el objeto de salida o del archivo hasta que todos los lectores hayan terminado. Los informes y las instantáneas JSON no mantienen la propiedad de los archivos. En los fallos de persistencia, inspecciona la fase de publicación y la durabilidad del error: puede devolverse un error después de que el destino ya se haya publicado. Consulta las garantías de salida.
