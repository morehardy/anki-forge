original-baseline-update http://127.0.0.1:63533/anki-forge/zh-cn/docs/updates/
用稳定笔记 ID 更新 Anki 牌组

为已经分发的 Anki 牌组发布修正或新增卡片。稳定笔记 ID 帮助 Anki Forge 和 Anki 识别已有笔记，而不是把它们当成新笔记；Anki 导入设置与较新的本地编辑仍会影响最终变化。

保持项目命名空间和笔记、模型、字段、模板键稳定。每个新版本都以上一版分发时的原始 APKG 为基准构建。包内包含完整的标识映射和修订信息，且这些信息采用带版本号的格式。请将原始包与对应的源码版本一起保存。

默认策略阻止 High 和 Critical 发现项。审阅特定类别后，调用方可有意选择 UpdatePolicy::default().allow(RiskCode::NoteRemoved)。它放行该类别中的所有发现项，同时保留原级别和证据；并不表示逐条批准指定笔记。没有匹配发现项的放行会产生警告；未知风险码被拒绝。不要自动放行比较返回的每一个码。

缺失或损坏的证据、命名空间不匹配、无效候选数据和检查限制都是硬错误，不是可放行的风险类别。分析无法完成时，比较返回错误及已完成的观察结果。对没有 update_from 的新建请求显式设置策略属于配置错误，与 setter 调用顺序无关。

证据与身份
章节：证据与身份

包内包含 ankiforge-identity.json，格式为 ankiforge-identity-v1。它将模型或配置 ID、笔记 GUID、历史字段或模板槽位、卡片或遮罩序号、修订和媒体绑定到实际集合与载荷。Anki 重新导出不保留该证据，不能作为更新基线。缺失证据绝不会被静默重建。

显示名称和内容编辑保留身份键。内容未变时保留基线修订；内容改变时推进修订。字段或模板重排保留历史映射。退役身份继续保留，恢复相同键时可复用。笔记键不能移到另一模型，模型键也不能在普通与 Cloze 类型间改变。

客户端导入行为与发布检查
章节：客户端导入行为与发布检查

APKG 是分发包，不是删除同步。省略笔记、字段、模板或遮罩，不会删除学习者已有数据。字段或模板 schema 和排序字段变化属于高风险，因为 Anki 合并与导入设置会影响行为。Schema 变化可能复制模型，或在笔记内容比较前更新目标笔记的时间戳。

在支持的客户端测试首次导入以及导入已有集合的更新。使用目标合并与笔记更新设置，检查字段、GUID、卡片集合、本地编辑和已有调度。仅稳定身份不保证较新本地编辑被覆盖，也不保证已删除的历史被恢复。

将候选包写到与归档基线不同的路径。审阅后分发被接受的包，并将它保留为下一次发布的证据。所有权和发布事实见构建保证。

troubleshooting http://127.0.0.1:63533/anki-forge/zh-cn/docs/troubleshooting/
排查问题

使用失败操作的结构化 kind 和 code，结合来源链与观察结果进行排查。显示文本面向人类，可能变化。操作失败与比较已完成但策略阻止发布，是不同的结果。

安装
章节：安装
现象	检查
Rust 拒绝工具链	运行 rustc --version；使用 Rust 1.92+，并以 cargo tree -i ankiforge 检查安装版本
Node 无法加载原生包	运行 node -p "process.platform + '/' + process.arch" 和 npm ls ankiforge；用 npm install --include=optional ankiforge@0.3.1 重装
Node 报告原生层与包装层不匹配	使用匹配版本；从相同 registry 版本重装，或从同一源码目录重建两者
Python 无法加载扩展	运行 python -m pip show ankiforge 和 python -m pip debug --verbose；检查解释器以及 wheel 的 OS/CPU 标签
Python 选择源码发行包	选择匹配 wheel/解释器，或按源码构建配置编译器

参见已验证环境、Node 安装和 Python 安装。

模型与笔记
章节：模型与笔记
现象	修正
无效或空键	显式提供稳定键；显示名称另行设置
NOTE.KEY_DUPLICATE	每条逻辑源记录使用唯一键
NOTE.FIELD_UNKNOWN	按字段键赋值，不使用显示名称
NOTE.FIELD_REQUIRED	添加前填写声明了 required() 的字段
NOTE.MODEL_CONFLICT	同一模型键复用相同的已完成模型
模板引用错误	使用已声明键；检查原始源码字节范围
HTML 显示为原文	仅对有意加入的标记使用 Content::html
缺少 Cloze 卡片	使用 {{c1::answer}} 语法，支持编号 1–500

添加失败是原子的。修正笔记或模型后重试，不需要撤销部分模型或媒体注册。模型构建器必须先完成 .build()，才能创建自定义笔记。

媒体与模板
章节：媒体与模板
现象	修正
文件导入失败	检查调用 Media::file 时的源文件；之后删除源文件是支持的
MIME 与内容不匹配	向字节构造函数传入实际 MIME 类型
导出名称冲突	选择唯一可移植名称；大小写与 Unicode 规范化变体也冲突
缺失原始 HTML/CSS/脚本资源	使用模型 asset 或项目 add_asset 声明
媒体导入超限	导入前显式提高 MediaLimits.max_bytes
构建检查超限	为本次操作调整相关 InspectLimits 计数器
模板包加载失败	使用 bundle-v2、显式键、按键模板以及包内路径
IO 矩形失败	检查解码后显示尺寸、有限坐标和唯一遮罩键

所有笔记类型的文本默认行为一致。媒体节点收集依赖；手写文件名不会导入其字节。即使包有效，仍需对计划使用的编解码器和字体进行客户端播放检查。

更新与输出
章节：更新与输出

基线应为含完整标识映射与修订信息的原始分发 APKG。Anki 重新导出的包不保留该证据。更新策略不能放行命名空间不匹配或证据损坏。

完成的比较可以有 allows_publication == false。选择显式风险类别放行前，检查原始发现项和证据。不要全部放行。若希望得到相同决策，必须向实际更新构建传入相同策略。在仅新建请求上设置策略会报错。

临时路径消失时，应将输出或产物所有者保留到全部读取者结束。报告和 JSON 快照不是所有者。持久化失败时，检查错误的发布阶段和持久性：目标已发布后也可能返回错误。参见输出保证。
