# 媒体优化收敛到原有接口

日期：2026-09-07。状态：已实现，相关回归及完整四档基准已完成。

按照用户要求，移除本轮新增、尚未发布的 `add_many()`，继续使用原有逐条注册和导出接口。默认临时导出内部自动批量准备、并行编码媒体，调用者不需要线程、队列或性能配置。

本机五场景 × 100、200、500、1000 四档的 20 个组合均快于同轮 genanki；17/20 达到耗时降低至少 30% 的目标。1000 条独立图片、独立音频、混合独立媒体分别降低约 20.84%、28.83%、29.66%，因此不能继续将旧批量入口的 20/20 成绩作为当前接口的结论。

## 接口及行为

```rust
for path in paths {
    let media = deck.media().add(MediaSource::from_file(path))?;
    // 按原方式创建笔记并引用 media。
}
deck.write_apkg("cards.apkg")?.ensure_success()?;
```

Project 的 `media_mut().add_file(path)?.export_as(filename)?` 和 `add_bytes()` 同样保持原用法。笔记、模板、MediaRef、build/write_apkg 和产物所有权接口没有因本次调整而改变。

每次 `add()` 返回前仍完整读取文件并保存内容指纹，立即检查同名不同内容；导出时仍核对注册后的来源变化。连续的同步调用不能在保持这种语义的同时自动并行注册尚未传入的文件。把全部哈希推迟到导出会改变报错时机，并失去原有注册时内容证据，本轮没有采用这种做法。

内部批量处理发生在构建已取得完整媒体列表之后。原有私有 PreparedMedia 流水线继续使用最多 4 个工作线程、有界队列、确定写入顺序及独立产物检查。注册时的读取继续同步，构建时的验证/编码自动并行；移除公开批量方法不意味着两者的耗时会相同。

## 本次内部优化

- Deck 文件注册的读取块从 8 KiB 调为 64 KiB，减少文件读取调用。
- 计算文件指纹时，复用首块数据解析常见图片的尺寸，避免为图片尺寸再次打开文件。
- JPEG 等格式的尺寸若位于较长头部之后，仍在同一个文件句柄上使用流式解析回退，不将整个文件读入内存。
- 去掉公开 `add_many()` 和基准专用 `--scalar-media` 分支；默认适配器直接循环调用原有 `add()`，元数据明确记录 `media_registration: individual`。

这些调整不引入延迟注册、后台线程寿命或用户配置。显式 `artifacts_dir`、`media_store_dir`、`base_dir`、self-contained 模式继续保留原有持久化路径，本次性能数据只覆盖默认临时导出。

## 当前默认调用的实测结果

素材来自可复现 v2 PNG/WAV 生成器；文字场景沿用 basic-mixed-text-v1。每格每实现 10 个独立计时进程、另做 5 次峰值 RSS 测量，每个阶段前分别预热 3 次。下表是 1000 条档位，RSS 为 5 次采样中的最大值。

| 场景 | Rust 中位数 ms | genanki 中位数 ms | 耗时降低 | Rust RSS 最高 MiB |
| --- | ---: | ---: | ---: | ---: |
| 纯文字 | 60.47 | 104.26 | 42.00% | 30.86 |
| 独立图片 | 236.81 | 299.15 | 20.84% | 40.08 |
| 独立音频 | 189.87 | 266.78 | 28.83% | 40.41 |
| 混合独立媒体 | 164.02 | 233.20 | 29.66% | 39.05 |
| 混合复用媒体 | 72.82 | 117.57 | 38.06% | 35.08 |

完整 20 个组合、IQR、内存及原始样本见[基准报告](../../../benchmarks/results/20260907-media-export-pr/report.md)与[证据目录](../../../benchmarks/results/20260907-media-export-pr/README.md)。不能将前后不同轮次的 genanki 耗时混合计算提速。旧批量入口结果保存在[历史实现报告](2026-09-07-media-performance-implementation-report.md)。

## 验证

- 本轮 261 项相关 Rust 测试通过：113 项库测试、4 项媒体优化测试，以及 144 项 Deck/Project 媒体、身份、序列化和导出测试。
- 新增回归覆盖普通 PNG、尺寸位于 64 KiB 之后的 JPEG、损坏图片、大于读取块的普通文件；文件注册与 inline 注册的指纹/尺寸一致。新增文件同名冲突用例验证同长度内容替换也在 add 时立即失败，注册状态保持不变。
- Python 基准行为测试 35 项通过；完整工作区所有目标的 Clippy `-D warnings`、格式及差异空白检查通过。
- 含预热的 840 次导出全部通过原始 SQLite 行/模板和精确媒体内容检查；其中 40 份 Rust/genanki 产物通过固定版本 Anki 后端实际导入、字段及媒体检查和代表性渲染。
- 420 份当前 Rust 产物的完整 APKG SHA-256 均与历史批量版相同场景/档位一致，见 `compatibility.json`。本次注册调整没有改变产物字节；上一轮顺序 ZIP 改动与更早版本的差异仍按 ADR 0018 说明。
- 完整基准期间源码、二进制、依赖、构建记录及输入身份前后一致。使用本机 macOS arm64、Rust 1.92、release/default features/system allocator、CPython 3.11/genanki 0.13.1。文件缓存未控制为冷缓存；没有宣称跨平台性能或 GUI/音频实际播放验证。

本轮没有提交或推送。设计说明见 [ADR 0018](../../adr/0018-build-owned-media-streaming.md)。
