## Rust

Package: <a href={`${repository}/tree/main/anki_forge`}><code>anki_forge</code></a>.

Use the core authoring API directly for Deck, Project, custom note types, media,
validation and update baselines. The source setup uses a local path dependency;
default contract resources are bundled with the crate.

Read the <a href={sitePath('/docs/rust-api/')}>Rust API guide</a> for common methods
and compiler-generated documentation instructions.

## Node and TypeScript

Package: <a href={`${repository}/tree/main/bindings/node`}><code>anki-forge-node</code></a>.

The native SDK owns Rust objects and provides asynchronous media/build operations,
ESM/CommonJS entry points and TypeScript declarations. Await operations on each
Project or Deck. The quickstart builds the host binary and can package it for a
separate local application.

## Python

Package: <a href={`${repository}/tree/main/bindings/python`}><code>anki-forge</code></a>;
import it as <code>anki_forge</code>.

Python 0.2 uses a native extension built with Maturin. Source consumers must build
the extension; a matching installed wheel does not need Cargo or contract tools.
The repository records wheel checks for four platforms on CPython 3.11 and 3.12.

Existing users should read <a href={sitePath('/docs/python-migration/')}>Python 0.1 to 0.2</a>.
For genanki users, the <a href={sitePath('/docs/genanki-migration/')}>migration guide</a>
explains fields, templates, HTML and media differences.

## Verify the release you intend to use

The <a href={sitePath('/docs/compatibility/')}>compatibility and release status</a>
page separates platform evidence, known limitations and publication. Check it
before adopting a registry dependency or committing to a platform.
